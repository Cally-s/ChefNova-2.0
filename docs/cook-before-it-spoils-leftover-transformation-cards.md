# Chef Nova Leftover Transformation Cards

## 1. Purpose

Leftover Transformation Cards present safe ways to use a prepared leftover without duplicating the Recipe Database or recipe-card system. Cards show projected use only; actual Pantry changes happen later through existing confirmation flows.

## 2. Existing Systems Reused

Step 19 reuses the Step 16 leftover inventory, Step 17 transformation ranking, Step 18 original timeline, Step 10 hard filters, Pantry allocation, Shopping List purchase groups, Cost Engine prices, Cook This Tonight planning, Freeze Options, Food Event History, and user-scoped storage.

## 3. Source Summary Model

The source summary model has version `1`. It records leftover batch ID, display name, prepared food identity, quantity, reservations, serving conversion, source meal, original recipe, timeline, storage, safety, current recommendation, and revision signatures.

## 4. Transformation Card Model

The transformation card model has version `1`. It records candidate ID, rule ID, source leftover ID, recipe ID, method, eligibility, projected source use, projected remainder, other priority Pantry food use, cross-rescue metrics, Pantry coverage, groceries, cost, cooking time, serving information, timeline warning, score, explanation, actions, and revisions.

## 5. Shared Recipe Card Extension

The existing `recipeCard()` renderer now accepts a `presentationMode: "leftover-transformation"` context. The shared card still owns recipe title, image placeholder, meta display, warnings, actions, responsive layout, and dialog entry points.

## 6. Projected Wording

Cards use `Would use`, `Projected source use`, `Projected quantity remaining`, and `Planned transformation` wording before confirmation. They do not say food was used, consumed, rescued, transformed, or waste was prevented.

## 7. Source Quantity and Servings

Available quantity comes from the canonical Pantry leftover batch and excludes active reservations. Servings display only when conversion status is confirmed. Unknown quantity remains unknown and is never shown as zero.

## 8. Reservations

Reserved leftover quantity is shown separately. Candidate generation and card display use only unreserved available quantity.

## 9. Original Timeline

Cards consume the Step 18 timeline result. Original cooked time remains visible and transformation time never replaces it.

## 10. Current Recommendation

Recommendation wording is derived from Step 6 guardrails and Step 18 timeline status: use today, use today with freeze review, use soon, review required, or not eligible.

## 11. Source Coverage

Source coverage is the projected source-leftover use divided by current unreserved source quantity. It is separate from Pantry coverage and other-priority-food coverage.

## 12. Other Priority Foods

Other priority Pantry foods appear only when they are eligible, unreserved, quantity-known, structurally matched, and meaningfully used.

## 13. Cross-Rescue Ranking

The existing transformation score now includes versioned cross-rescue components. Source-leftover coverage remains the strongest factor, while meaningful use of other priority foods can improve otherwise comparable candidates.

## 14. Trace-Use Protection

Trace garnish quantities can still count as proportional Pantry use, but they do not receive full meaningful-use credit or “also uses food that needs attention” wording.

## 15. Pantry Coverage

Pantry coverage describes how much of the complete transformation recipe is covered by Pantry. It is not the same as source-leftover coverage.

## 16. New Groceries and Cost

Cards display Shopping List purchase groups, full-package marginal cost, and incomplete pricing honestly. Missing prices are not displayed as `$0.00`.

## 17. Cooking and Serving Information

Cards use the selected preparation method, effective cooking time, suggested servings, and unallocated target servings from the existing transformation and scaling flow.

## 18. Recommendation Explanations

Explanations reuse structured candidate evidence and remain concise.

## 19. Add to Tonight

Add to Tonight appears only for candidates targeting today. The action opens the existing review flow and does not reserve, deduct, or complete food from the preview card.

## 20. Plan for Another Meal

Plan for Another Meal appears only for future eligible target dates generated by the existing path engine. It does not extend the source timeline.

## 21. View Details

View Details uses the existing transformation path details modal and includes source, timeline, Pantry, cost, safety, and projected-use context.

## 22. Find Another Use

Find Another Use uses a temporary projected remainder ledger. It filters candidates to the projected remainder and does not mutate the actual leftover batch.

## 23. Multi-Meal Paths

Multi-meal path actions reuse the Step 17 path interface and path model.

## 24. Freeze for Later

Freeze for Later is a preservation option card, not a recipe card. It appears only when Step 6 and Step 18 permit freeze review.

## 25. Partial Freezing

Confirmed partial freezing remains the Step 16 batch split workflow. Opening options does not freeze food.

## 26. Review and Exclusion States

Review-required and hard-excluded sources show review messaging instead of automatic transformation cards.

## 27. Data-Mutation Boundaries

Viewing cards, details, comparisons, Add to Tonight, Find Another Use, and Freeze Options do not change Pantry, reservations, calendar, Shopping List, child batches, or Food Event History.

## 28. Stale-Result Protection

Cards store source, rule, score, timeline, price, calendar, event, and user-scope revision data. Actions revalidate through existing path generation before confirmation.

## 29. User Isolation

Registered users use user-scoped Pantry, plans, prices, events, safety reviews, and preferences. Guest cards use temporary guest state and do not persist into registered-user storage automatically.

## 30. Accessibility

The panel uses visible headings, semantic lists, labelled metrics, specific action names, textual status, modal focus behavior, and live-region announcements.

## 31. Responsive Design

Source summary metrics and card metrics stack on small screens. Actions wrap without a separate mobile card system.

## 32. Print and Export

Print output keeps source summary, projected wording, transformation cards, safety notice, timeline warning, groceries, cost, and cooking details while hiding interactive controls.

## 33. Testing

Validation covers syntax, data parsing, ingredient and price validation, existing test suite, and the Step 19 static test.

## 34. Deferred Work

Automatic transformation, automatic freezing, waste analytics, household-pattern learning, and environmental-impact claims remain outside Step 19.
